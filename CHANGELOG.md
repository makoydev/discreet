## [Unreleased]

### Added

- Go 1.27 project skeleton: the `discreet` command with `serve`, `audit verify`, `audit export` and `version`, each describing itself until it is built (issue D1).
- CI on every pull request: `gofmt`, `go vet`, `go test -race`, `govulncheck` and a build (`make check`), plus CodeQL for Go and the workflows. All Actions pinned by commit SHA.
- Evidence files: `CONTROLS.md`, `THREAT_MODEL.md`, `EVALS.md`, `RISKS.md`, `docs/HOW-THIS-WAS-BUILT.md` and the first two decision records.
- Vetted reviews every pull request (shadow mode until 2026-10-14).
- Detection engine (`internal/detect`, issue D3): implements the sg-pii-rules specification with Go's `regexp` (RE2), including the five named validators (NRIC/FIN, NRIC look-alikes, payment cards, postal sectors, calendar dates), `value` groups and the overlap rule. Passes all 369 shared conformance cases.
- Four-pane demo page (issue D8) at `/`: what the app sent, what the AI saw, what it answered, and what the app got back, plus that request's audit record. Five made-up scenarios (claims, appointment, card dispute, mistyped NRIC, a refused eligibility decision). It runs through the same pipeline as the API, always on the mock model, even for token holders; strict Content-Security-Policy; works on phones, light and dark.
- A real model behind access tokens (issue D6): an OpenAI-compatible client (OpenAI, or Ollama with `max_tokens`) used only for callers with a valid `DISCREET_ACCESS_TOKENS` token; everyone else gets the mock. One pinned model with checked prices (`gpt-6-luna`); each request reserves its worst-case cost (at most US$0.0076) against a hard daily budget (default US$0.20) recomputed from the audit log; 30 requests a minute per client address (ADR 0007). No test calls a paid API.
- The gateway (`internal/gateway`, issue D5): `discreet serve` runs an OpenAI-compatible `POST /v1/chat/completions` (non-streaming). Every message is protected in one session before the model sees it and restored afterwards; every answer ends with a disclosure footer; every request, allowed or not, is recorded in the audit log, and Discreet never answers a request it couldn't record. A free mock model is the default. Callers must send `X-Discreet-Purpose`; automated eligibility and benefits decisions are refused with HTTP 403 (ADR 0006). Only the model, messages, token limit and temperature are forwarded. Tested with OpenAI's official Python library by changing only `base_url`.
- Tamper-evident audit log (`internal/audit`, issue D7): append-only JSON lines, each record holding the SHA-256 of the previous one and HMAC-SHA-256 hashes of prompt and response (never the text). `discreet audit verify` names the first changed, missing or reordered record; `discreet audit export -csv` exports a verified log. An existing broken log is refused at start-up (ADR 0005).
- Placeholders and the vault (`internal/protect`, `internal/vault`, issue D4): personal data is replaced per request with numbered placeholders such as `<NRIC_1>` (the same value gets the same placeholder), redacted as `[REDACTED_CARD]`, or the request is blocked, following a YAML policy (`internal/protect/default-policy.yaml`). Values are kept encrypted in memory with AES-256-GCM for at most 10 minutes and restored only into the same request's answer (ADR 0004). First third-party module: `go.yaml.in/yaml/v3` v3.0.5.
- sg-pii-rules `v0.2.0-rc.1` vendored in `third_party/sgpiirules` and embedded in the binary; a test re-checks every file against `SHA256SUMS` (ADR 0003). `scripts/vendor-sg-pii-rules.sh <tag>` updates it.
