# Controls matrix (v0.1)

What each part of Discreet supports, with source and section. **P** = primary source, **S** = secondary. The citations below were read from the primary sources for [Vetted's controls matrix](https://github.com/makoydev/vetted/blob/next/CONTROLS.md#sources) on 2026-09-30 and are reused here where Discreet implements the same principle; "by analogy" marks guidance written for a neighbouring case. No row claims compliance with a law or framework: each says which principle a feature supports.

| #   | Feature | Supports | Source (grade) | Evidence |
| --- | --- | --- | --- | --- |
| 1   | Personal data replaced with placeholders before the model sees it: NRIC/FIN (including mistyped), phone, email, card, postal code, unit number, date of birth; values restored only into the same request's answer | Protecting personal data; not disclosing NRIC numbers that aren't needed; pseudonymising before use in AI | PDPA 2012 s.24 Protection of personal data (P) · PDPC _Advisory Guidelines on Use of Personal Data in AI Recommendation and Decision Systems_ ¶7.2, pseudonymise as a basic control (P, by analogy) · PDPC _Advisory Guidelines for NRIC and other National Identification Numbers_ §3.1 (P) · OWASP LLM02:2025 Sensitive Information Disclosure (P) · IMDA _Starter Kit for Testing LLM-Based Applications_ §3.5 Data Leakage, which names NRIC (P) | 369/369 shared conformance cases; gateway test that the model never receives a planted value; EVALS benchmark |
| 2   | Values kept only encrypted in memory (AES-256-GCM, per-process key), deleted when the request ends, expired after 10 minutes, never logged | Protection of personal data in the processor itself | PDPA s.24 (P) · CSA _Guidelines on Securing AI Systems_ (Oct 2024) 2.3, protect data and logs (P) | `internal/vault` tests; log scan test (ADR 0004) |

## Gaps (planned for Milestone 3 or later)

- **Hold-for-review queue** with reviewer decisions and override rates (IMDA MGF for Agentic AI asks for monitoring human override rates and response times).
- **Policy presets** `sg-healthcare` and `sg-finance` (MAS FEAT, MOH AI in Healthcare Guidelines, HIPAA Safe Harbor identifiers).
- **Project Moonshot** data-disclosure and adversarial-prompt run (IMDA Starter Kit).
- **Person names** (needs NER) and the writing styles the benchmark shows the rules miss.
- **Anchoring the audit log's head hash** outside the server (ADR 0005).
- Each row above should be re-read against the current edition of its source before v1.0.
